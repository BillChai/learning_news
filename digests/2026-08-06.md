1. **[工程知識/效能] Branchless Rust：拿掉一個 if，讓過濾器快 4 倍**
   把「條件判斷要不要保留元素」的 if 改寫成「永遠寫入，用比較結果（0 或 1）決定游標要不要前進」的純算術寫法，藉此消除分支預測失敗在隨機資料下造成的 pipeline flush 代價。用具體 benchmark 展示分支消除技巧的實戰教材。
   來源：greyblake.com — <https://www.greyblake.com/blog/branchless-rust/>｜發布：2026-08-02｜配額類別：工程知識/教學｜來源類型：優先來源清單（Hacker News）

2. **[工程知識/系統] 把 RISC-V 模擬器推到極限：AOT 重編譯器實作**
   從基礎 interpreter 一路疊加 predecoding、computed goto dispatch、tail-call threading，最終把整個 basic block 轉譯成 C 程式碼再編譯；用 `preserve_none` calling convention 把熱路徑的 guest 狀態留在 host 暫存器裡，並用 tail call 串接產生的 basic block。在 LZ4、zstd 等真實負載上達到原生效能的 84–89%。
   來源：shuklaayu.sh — <https://shuklaayu.sh/blog/riscv-recompiler>｜發布：2026-07-26（較早）｜配額類別：工程知識/教學｜來源類型：優先來源清單（Hacker News）

3. **[工程知識/架構] Webhook 之谷：為什麼推播式同步天生就不適合資料複製**
   作者在三家不同公司重複打造同一套 webhook 整合系統，每次都得補上簽章驗證、去重表、緩衝、bootstrap importer、夜間對帳 cron——全是在彌補 webhook 模型的先天缺陷。他主張應該反過來：consumer 主動拉取一份「有序、可用游標定位」的變更日誌，而不是被動等 provider 推播，這樣能天生具備驗證與防止「已取消的客戶仍顯示為啟用」這類靜默漏資料的問題。
   來源：weli.dev — <https://weli.dev/blog/the-valley-of-webhooks/>｜發布：2026-08-05｜配額類別：工程知識/教學｜來源類型：優先來源清單（Hacker News）

4. **[工程知識/AI] Goodhart 定律追上了你信任的每一個 benchmark**
   借 Goodhart 1975 年的觀察「一旦measure變成target，它就不再是好measure」，對照 No Child Left Behind 讓老師教學生「應付考試」而非真正學習、以及機器翻譯years砸在優化 BLEU 分數卻譯得爛的歷史，指出 AI 圈正重複同一個模式——benchmark 分數已經在決定誰能募資、企業買哪個模型、媒體寫什麼稿。作者主張真正該問的不是「如何做出無法被打分技巧攻破的 benchmark」，而是「如何在明知每個被信任的 benchmark 都已經部分失真的情況下，仍然做出決策」。
   來源：Communications of the ACM（Alex Williams）— <https://cacm.acm.org/blogcacm/goodharts-law-comes-for-every-benchmark-you-trust/>｜發布：2026-07-28（較早）｜配額類別：工程知識/教學｜來源類型：優先來源清單（Hacker News）

5. **[工程知識/DB] COUNT(DISTINCT) 太慢？PostgreSQL 近似計數技巧指南**
   在千萬行資料集上實測三種近似技巧：`TABLESAMPLE` 隨機抽樣但對 distinct count 效果不佳；`hll` 擴充套件的 HyperLogLog 提供機率型計數且 sketch 可合併，適合預先聚合；Apache DataSketches 最完整，除了 distinct count 還支援 Theta sketch 做集合運算、KLL sketch 做分位數估計，讓「找出透過多個管道來訪的使用者」這類查詢不必重新掃描原始資料。
   來源：Snowflake Engineering Blog（Elizabeth Garrett Christensen）— <https://www.snowflake.com/en/blog/engineering/postgres-count-distinct-approximation/>｜發布：2026-07-31｜配額類別：工程知識/教學｜來源類型：優先來源清單（Postgres Weekly #660 選文）
