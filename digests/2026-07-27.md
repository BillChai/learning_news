1. **[工程知識][AI] From Tokens to Answers：一次 LLM 推論到底發生了什麼**
   從 tokenization → embedding → prefill（整段 prompt 平行處理、GPU 跑得快）→ decode（逐 token 生成）→ KV cache（快取先前的 attention key/value，避免每步重算整段 context），把「推論」這件每天在用卻常被當黑盒的事拆到第一原理，並點出 decode 階段其實卡在記憶體頻寬。做 LLM 應用後端、想搞懂延遲與成本從哪來的必讀。
   來源：Turing Post — <https://www.turingpost.com/p/llm-inference-from-tokens-to-answers>｜發布：2026-05-21（較早）｜配額類別：工程知識/教學｜來源類型：開放搜尋補充

2. **[工程知識][DB] Understanding Database Sharding**
   把資料庫分片講清楚：key-based（雜湊分片、避免 hotspot 但擴容要 remap）、range-based（好實作但易分布不均）、directory-based（查表最靈活但多一層失敗點）三種策略的取捨，並強調「分片是最後手段」——先窮盡 caching、read replica、垂直升級再說。理解水平擴展代價的扎實教材。
   來源：DigitalOcean Community — <https://www.digitalocean.com/community/tutorials/understanding-database-sharding>｜常青教學（依內容深度納入）｜配額類別：工程知識/教學｜來源類型：開放搜尋補充

4. **[工程知識][分散式] CAP、PACELC、ACID、BASE：架構師工具箱的必備概念**
   一次釐清四個最常被混用的分散式理論：CAP 講「分區時只能二選一」，PACELC 補上「沒分區時，仍要在延遲 vs 一致性之間取捨」（DynamoDB＝PA/EL、CockroachDB＝PC/EC），再帶到 ACID 與 BASE 兩種資料一致性哲學。挑資料庫/存儲時想講得出「為什麼選它」的理論底子。

5. **[工程知識][系統設計] Caching：策略、淘汰、失效與常見故障模式**
   系統性整理快取：四種讀寫模式（cache-aside / read-through / write-through / write-behind）、淘汰策略（LRU/LFU/FIFO/TTL）、一致性與失效（更新 DB 後刪除快取 key），以及三大故障——cache stampede（過期瞬間一擁而上重建）、快取與 DB 不一致、hot key 打爆單節點。做後端快取設計前先過一遍。
   來源：Hello Interview（System Design）— <https://www.hellointerview.com/learn/system-design/core-concepts/caching>｜常青教學（依內容深度納入）｜配額類別：工程知識/教學｜來源類型：開放搜尋補充

9. **[架構][DB] DoorDash 用 Envoy＋Valkey 打造 1.5M RPS 的 Proxy Cache，可用性 99.99999%**
   DoorDash 的 Entity Cache 是一層透明代理快取，架在 Envoy service mesh 裡攔截 HTTP/gRPC，命中就直接回、未命中才打上游。跨 50 服務、100+ 端點、每秒 150 萬請求，命中率 >90%、正常情況少打上游 60–95%。工程亮點：custom buffer pool、lock-free single-flight 防重複回源、XFetch 機率式提前刷新（讓吞吐 ×5、P99 尖峰降 80%），並用 Kafka 事件失效＋雙 TTL 在故障時「寧可回稍舊資料也不掛」。真實世界的快取架構教材。
   來源：InfoQ — <https://www.infoq.com/news/2026/07/doordash-entity-cache-proxy/>｜發布：2026-07-20｜配額類別：更廣泛後端（架構/DB）｜來源類型：優先來源清單（InfoQ）
